## 2. R06-REV-1 — blocking. B16 never reaches the ADC return

`/B16` contains exactly two nodes: `J2.6` and `U2.2`, the opto LED cathode.
`/AGND` contains the two divider bottoms (`R8.2`, `R11.2`), both filter
capacitors, both lower clamps, `TP18` and `U1.33`. **The two nets are never
joined, by a wire, a label or a net tie.**

So the cluster's ground-sense conductor lands on the optocoupler and stops
there, and both ADC channels reference the Pico's local analog ground instead.
That is precisely the error B16 exists to prevent: any cluster-to-logger ground
offset now lands directly in the fuel and supply readings, uncorrected.

This contradicts three sources at once:

- `AS_BUILT` §2 row 8 — B16 "lands on a breadboard ground rail jumpered to Pico
  AGND; both ADC divider bottoms use that same rail."
- `REV_A_INTERFACES` §4 — "one conductor from the cluster, bonded at the logger
  end only, carrying both ADC divider bottoms to a single node, then to ADC
  AGND."
- `D5`, whose entire content is making that single-point return explicit so
  layout cannot lose it.

**This reads as an omission, not a disagreement.** `CAPTURE_NOTES` Q7 states
that `TP_GND_HARNESS` sits "on the B16 sense node", and `TP18` is on `/AGND` —
so the capture already treats `/AGND` as the B16 sense node. The intent is
right; the conductor from `J2.6` simply was not brought to it.

**Required:** bond `J2.6` to the `/AGND` node at one point, so the net carries
the cluster conductor, both divider bottoms, both clamp/filter returns and
`U1.33`. Then read R06-REV-2 before deciding where the opto LED returns,
because the two interact.

## 3. R06-REV-2 — escalated, not a capture defect. D5 and the fitted LED return are incompatible

The capture's Q2 is correct and the contradiction is real, but it is sharper
than the return states, and fixing R06-REV-1 is what sharpens it.

Today the LED current has nowhere to go but off-board, because B16 is isolated.
Bond B16 to AGND as D5 requires and **4.7–5.8 mA of optocoupler LED current
flows through the ADC reference node** every time the engine runs. A common-mode
offset largely self-cancels in the fuel computation; a few milliamps of
signal-dependent current in the reference conductor does not.

So one of these has to give, and it is an electrical decision, not a capture
one:

- Return the LED to PGND, as `DESIGN.md` §3 does, and keep B16 reference-only.
- Keep the fitted B16 return and abandon the single-point ADC bond.
- Something else that satisfies both.

Also unresolved and now measurable: with the board off, a 16 V B11 still drives
that LED. Given what B2 turned out to be, a second energized path into an
unpowered board is worth measuring rather than assuming. **Owner: this one needs
the key on, so it is not a driveway reading.**

**Assigned to the electrical lead, with the analog reviewer.** LRA-06 is correct
not to have chosen.

## 8. R06-REV-4 — blocking, found on a second pass against candidate `1d14604`

**The input TVS is reversed, and it is the one part `DESIGN.md` says must be
checked.**

Evidence chain, each link verified rather than assumed:

1. The BOM specifies **Vishay 1.5KE30A-E3/54**. The plain `A` suffix is the
   **unidirectional** device; `1.5KE30CA` is the bidirectional one.
2. The symbol used is `Device:D_TVS`, whose pins are named **`A1` and `A2`** —
   a bidirectional symbol. It has no cathode, so the schematic expresses no
   polarity and **ERC cannot flag this**. `Diode:1.5KExxA` is no better; it uses
   A1/A2 too.
3. The footprint is `Diode_THT:D_DO-201AD_P12.70mm_Horizontal`. **Pad 1 is the
   banded cathode end** — the silkscreen band sits at x ≈ 2.9–3.1 mm, against
   pad 1 at x = 0, with pad 2 out at x = 12.7.
4. The netlist puts **`D111.1` — pad 1, the banded end — on `/PGND`**, and
   `D111.2` on `/P12`.
5. `DESIGN.md` §3 requires the opposite: *"P12 -- TVS cathode; TVS anode -- PGND"*.

So the board as drawn solders the banded end to ground. A unidirectional TVS
mounted that way is simply a forward-biased rectifier across the supply: it
conducts at roughly a volt and **shorts P12 to PGND**.

`DESIGN.md` anticipated exactly this failure, in as many words:

> *"For each diode the band is the cathode; check its net rather than relying on
> vertical footprint names. The hondaPico TVS reversal history makes that check
> essential."*

The BOM row carries that warning forward. The warning was written down and the
check still could not be performed, because the chosen symbol deleted the
cathode the instruction refers to.

**This is not a careless capture.** A full polarity audit of all fourteen diodes
against `DESIGN.md` and `AS_BUILT` found **thirteen correct** — every clamp, both
ADC pairs correctly opposed, `DREV`, `DZ`, `DCATCH`, `DOR`, `DI` and `DR` all
right way round. The single failure is the one component whose symbol carried no
polarity to check. That is a tooling trap, not inattention, and it is worth
recording as such.

**Required:**

1. Put pin 1 on `/P12` and pin 2 on `/PGND`, so the banded end faces the supply.
2. State the pin-to-band mapping explicitly in `CAPTURE_NOTES` — "pin 1 is the
   banded cathode end, footprint pad 1" — because no available symbol encodes
   it and the next reader will face the same trap.
3. Add a check asserting TVS pin 1 is on `/P12`. The existing suite cannot
   catch polarity on an A1/A2 symbol, which is the same class of gap that let
   REV-1 through.

If the electrical lead instead wants a bidirectional device, that is a BOM
change at R02 and `DESIGN.md` §3 needs amending to match; it is not resolved by
leaving the current orientation in place.
