## Required dispositions

| Item | Review decision and remaining gate |
|---|---|
| Direct alarm and startup | Accept exclusive channel allocation on core 1, highest IRQ priority, LOW preload/4 mA drive and fail-closed resource exhaustion for candidate development. Installed SDK and compiled IRQ inspection support the implementation. Actual boot-to-HOLD and callback latency remain unmeasured. |
| Interrupt masking / XIP | **Acceptance blocker remains.** A foreground SDK spinlock wait with interrupts masked can prevent the supervisor running. With a last watchdog feed immediately before a stall near OFF+1800 s, a nominal 4 s reset timeout does not prove HOLD LOW by OFF+1801 s. The handoff explicitly discloses this limitation. Review/quantify the supported fault envelope or change the implementation/timing allocation before claiming that bound; do not close it with the native policy tests or normal-load measurements alone. |
| Watchdog | Accept fixed 8 s startup grace, readiness per core, <=2 s foreground freshness, latched failure and 4 s non-debug-pausing watchdog as candidate choices. Grace ends per ready core; IRQ activity does not refresh foreground health. Approximate maximum startup reset delay is 12 s from supervisor installation, not power-on; runtime reset can take about 6 s after last foreground progress. Physical reset coverage, pad release and worst-case healthy SD/USB/ADC latency remain open. |
| New file on observed ON return | Accept the conservative rotation even when return precedes finalization. Old drain/close is serialized before new recording. Pulse counters and sample columns remain continuous; each file has its own header/upload identity. Observe possible recording gaps and file proliferation in real trials. |
| Producer / failed media | Accept complete-line stop acknowledgment, stable queue watermark and explicit whole-record loss policies. After failed media, abandoning the old queue prevents a suffix from becoming the new file's first row. Close diagnostics are evidence only, never authority for HOLD. Physical partial-write/reinsertion tests remain necessary. |
| USB and metadata | Accept additive `log.power` and best-effort qualified USB output; manual USB policy remains historical. Qualified USB bytes cannot be treated as a lossless card copy. Public converter checks pass; no private DB behavior is certified. |
| Manual default / rollback | No GP6 power setup, application watchdog or power alarm in default mode. The manual candidate still changes version/header metadata and uses the atomic SPSC queue; exact pre-task rollback is base `2c52afd`, not merely selecting mode 0. |

The masked-interrupt issue is a known limitation of the submitted candidate,
